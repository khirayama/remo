# Remo Android

Jetpack Compose製のタイムラインアプリです。認証トークンはAndroid Keystoreで保存し、Timeline recordのメタデータは端末を正本として保存します。ログイン中は写真ごとの縮小JPEGをバックアップし、別端末ではクラウドの画像を表示します。

初回起動時に位置情報の許可を確認し、許可後はForeground Location Serviceが自動で位置を記録します。通常は10秒間隔で取得し、直近数分の座標・速度が安定し、利用可能な静止センサー／Activity Recognitionも静止を示す場合だけ5分間隔へ移行します。5分モード中はモーション・歩数・大きな動き・Activity Recognitionを監視し、移動の可能性を検知すると即座に10秒間隔へ戻します（設定から停止できます）。Google Mapsには現在地を表示し、位置ログは線だけで表示します。日付・PHOTOS・時系列の記録一覧は下部シートにまとめています。写真ライブラリは撮影日時とEXIF位置だけを端末内で読み込みます。

写真一覧から写真を開き「位置を補正」を選ぶと、写真自身を除外した、撮影時刻の前後15分以内にある精度100m以下の加工済み位置ログから候補を表示します。未確定のEXIF写真は地図・Timeline上でもその加工済み位置へ表示上自動配置します。候補の適用、地図タップ、緯度経度の手入力、位置情報の削除、元のEXIFへの復元に対応し、元のEXIFへ戻した写真は自動配置しません。写真を同じ日・同じ位置でまとめているため、補正単位は写真グループです。元のEXIF位置は端末と同期データに保持します。

選択日内の滞在ポイントは、代表座標が100m以内の別滞在を同じ場所としてまとめ、訪問回数ごとに表示します。端末のGeocoderが返すプレイス名・住所を滞在ポイントと地図ポップアップに表示します。住所は端末内の表示用で記録・同期データには保存しません。訪問履歴から場所に名前を付けると、その名前を優先して表示し、ログイン中は同期します。

設定画面から開始日・終了日を指定して、位置と写真メタデータをJSONへエクスポートできます。JSONのインポートにも対応し、読み込んだ記録は端末へ統合してバックアップします。元写真・動画本体は端末外へコピーせず、縮小画像だけをバックアップします。設定画面ではバックアップ状況も確認できます。

## Androidの保存・描画・省電力設計

- 移動中の測位要求は従来どおり10秒間隔です。低精度モードへの変更や経路の座標点の間引きは行いません。30秒を超える古い測位・重複・逆順の測位を除外し、粗い位置の直後2秒以内に届く、十分に精度が良い位置で同じ記録を更新できます。
- 静止判定は単調時計で3分以上の連続した証拠を確認します。精度50m以下・速度・サンプル間隔を検証し、実際に登録できた移動検知手段がある場合だけ5分モードへ移行します。移動検知時には証拠をリセットし、通常モードに戻します。端末ごとのセンサー性能と復帰遅延は実機での評価が必要です。
- 記録は共通のSQLite Repository（`LogStore`、型付きの列）へバックグラウンドで保存します。メモリに持つのは表示中の1日と写真記録だけで、他の日・エクスポート・未バックアップの記録は開始時刻と同期状態のインデックスから読みます。旧SharedPreferencesのJSONと旧DB（JSON文字列1列）は初回にトランザクション内で移行します。全データ削除時には移行元も削除し、削除前に開始した保存処理は破棄します。
- 端末の再起動後とアプリの更新後は`BootReceiver`が記録を再開します。バックグラウンドからの開始をOSが拒否した場合は、アプリを開くよう通知します。
- 記録の書き込みに失敗した場合（空き容量不足など）は、画面にメッセージを表示します。
- 前景でのバックアップ試行は最大1分に1回にまとめます。変更がなければ15分間は通信せず、画面非表示中はネットワーク接続を条件とするWorkManagerの15分周期の処理へ任せます。まだバックアップしていない記録と削除だけを400件ずつ送り、応答ごとに送信済みにします。クラウド側の差分読み取りは最新カーソルが進んだ場合だけ行い、受け取ったページごとに保存します。他の端末の編集は新しければ取り込み、他の端末で1件ずつ削除された記録は端末からも削除します。OSにより実行が遅れることがあります。
- 地図とシートの集計をバックグラウンドスレッドで準備・共有し、画面非表示中や設定タブでは集計の購読を停止します。滞在判定は中央値を逐次更新します。同じ色の連続経路を座標を省略せずまとめ、ネイティブ地図上の線・マーカーは差分更新します。地図の終了処理は一度だけ実行します。
- 写真バックアップは、写真ライブラリと写真記録が前回の完了時から変わっていなければライブラリを走査しません。ライブラリから消えた写真のプレビューは、記録に残っているプレビューの一覧を送ってクラウドから削除します。
- 写真は更新日時・サイズ・権限・MediaStoreの世代に応じてEXIFキャッシュを無効化します。写真グループは完成した集計だけを保存し、内容が変わらなければDB更新しません。サムネイルと住所は上限付きでキャッシュします。写真グループのIDや既存の補正単位は維持します。

## 検証

通常のビルド・単体テスト:

```bash
rtk proxy ./gradlew testDebugUnitTest lintDebug assembleDebug
```

接続済みエミュレーターで保存移行と描画のテストを実行できます。描画テストは2,000件の記録を作るため、既存アプリと異なるapplicationIdを指定してください。通常のapplicationIdでは描画テストをスキップします。

```bash
rtk proxy ./gradlew connectedDebugAndroidTest -PapplicationId=com.remo.app.optimization
```

消費電力の削減率は実機で未測定です。画面オフの静止・徒歩・車移動・GPSが不安定な屋内で、電池消費とあわせて移動開始の検知遅延、記録欠落、位置誤差を比較してください。

リリースビルドはR8で縮小します。ストアへ出すビルドは `-PversionCode=<n> -PversionName=<x.y.z>` を指定してください。

Maps APIキーは`local.properties`の`mapsApiKey`、または`MAPS_API_KEY`環境変数で渡してください。

```bash
./gradlew assembleDebug
MAPS_API_KEY=your-key ./gradlew assembleDebug
```

エミュレータからはデフォルトで`http://10.0.2.2:8787`を使います。別のAPIを指定する場合は次のように実行します。

```bash
./gradlew assembleDebug -PapiBaseUrl=http://10.0.2.2:8797
```
