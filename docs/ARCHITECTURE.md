# Remo architecture

## Product loop

Remoの実装境界は`Capture → Timeline`です。

1. 通常10秒間隔、十分な静止判定後だけ5分間隔へ切り替えて位置を取得する（Webはタブ表示中のみ）。
2. 端末が写真ライブラリから撮影日時とEXIF位置を読み、最新側から段階的にTimelineへ反映する。
3. 端末内の記録を日付と時刻で並べ、地図の軌跡とTimelineへ表示する。
4. 記録は未ログインでも端末へ保存し、認証済みユーザーだけが記録メタデータと縮小写真をAPIへバックアップする。

認証はTimelineの利用条件ではなく、バックアップのための機能です。起動時はログイン画面へ遷移せず、設定からユーザーがバックアップを開始します。ログアウトしても端末内の記録は残し、別端末やWebでの閲覧はログイン後に行います。

## Data model

1件のTimeline recordは次の情報だけを持つ。

- `id`
- `startedAt`
- `latitude` / `longitude`（任意）
- `originalLatitude` / `originalLongitude`（写真の元のEXIF座標、任意）
- `locationSource`（写真の位置の由来。`exif` / `inferred` / `manual` / `removed`、任意）
- `photoLocationAutoPlacementDisabled`（元のEXIFへ明示的に戻した写真の自動表示配置を無効化、任意）
- `mediaType`（写真イベントの種別。`photo` または `video`、旧データは写真として扱う）
- `photoCount`
- `source`（`location` または `photo`）
- `updatedAt`

元写真は端末内に保存する。ログイン中は写真ごとに縮小・再圧縮したJPEGを同期APIへ送り、R2へ保存する。動画本体は送らない。写真位置を補正した場合も、元のEXIF座標は保持する。未確定のEXIF写真だけは、補正済み位置ログから求めた候補を地図・Timelineの表示座標に使うが、保存座標は変更しない。元のEXIFへ明示的に戻した場合は、自動表示配置を無効化する。

## Storage

| データ | 保存先 | 備考 |
| --- | --- | --- |
| Webの記録 | `localStorage` | 端末固有ID単位。認証状態に依存しない |
| Webの未同期操作と同期カーソル | `localStorage` | バックアップ先のユーザー単位で分離 |
| iOSの記録と写真 | `UserDefaults` | 元写真は端末内、縮小JPEGはR2へバックアップ |
| Androidの記録と写真 | `SharedPreferences` | 元写真は端末内、縮小JPEGはR2へバックアップ |
| バックアップメタデータ | Cloudflare D1 | ユーザー単位で分離。端末データを正本とする。`updated_at`はユーザー単位で単調増加し、差分同期カーソル`(updated_at, id)`の取りこぼしを防ぐ |

## Capture

### iOS

初回起動時に位置情報の許可を確認し、許可後は自動でCore Locationを開始する。位置情報の「常に許可」があればバックグラウンドでも動作し、通常10秒間隔、直近3分の移動変位・速度・モーションによる十分な静止判定後は5分間隔へ自動で切り替える。設定から停止できる。

### Android

初回起動時に位置情報と、利用可能ならActivity Recognitionの許可を確認し、許可後は通知を伴うForeground Location Serviceを自動で開始する。通常はFused Location Providerを高精度・10秒間隔で更新し、直近3分以上の有効な位置サンプルで座標差と速度が静止条件を満たし、静止センサー／Activity Recognitionが移動を示さない場合だけ、バランスド電力・5分間隔へ切り替える。5分モード中はモーション検出、歩数検出、有意な動き、Activity Recognitionの移動状態を監視し、検知時は即座に10秒間隔へ戻す。設定から停止できる。モード変更理由はAndroidログと端末内設定へ保存する。

### Web

初回表示時にブラウザの位置情報許可を確認し、許可後は`getCurrentPosition`を即時実行して、その後通常10秒間隔、直近の位置変位・速度による静止判定後は5分間隔で定期取得する。ブラウザを閉じた後の取得は行わない。設定から停止できる。

## Timeline

表示対象の日付を1日単位で切り替える。選択日だけの記録を時刻順に地図へ渡し、位置ログと座標付き写真を時系列の位置サンプルとして扱う。地図には、精度フィルター（精度100m超を除外）後のスパイク補正と滞在区間の集約を行った加工済みの移動線だけを表示する。滞在判定は生座標を使わず、位置ログと写真を含む精度フィルター後のスパイク補正済み位置だけを入力にする。精度の悪い点は加工済み移動・滞在・自動ズームから除外するが、元の記録とTimeline一覧には残す。初期表示の地図範囲は加工済み位置・滞在・写真を基準にする。滞在判定は3段階で行う。(1) 連続する位置点が80m以内（測位精度が80mより悪い点は精度の値まで、最大100m）にまとまる区間を候補にする。(2) 同じ場所（中心が80m以内）に戻る候補どうしは、間がサンプルのない12時間以内の欠測（iOSは静止中に50m移動するまで更新が届かないため）、3分以内の一時的な外れ、または全点が200m以内に留まるふらつきならつなぎ、間に別の滞在があればつながない。3サンプル以上かつ5分以上続くものだけを滞在とする。(3) 屋内ではWi-FiとGPSの測位が数百m離れた2点の間を行き来することがあるため、隣り合う滞在は、中心が200m以内、または500m以内で一方の滞在中に他方の場所の測位（補正前の座標）が2割以上混ざる場合に、間が移動でなければ1つにまとめる。間は、(2)の条件か、300mより遠い点が3割以下、または元の場所の測位が2割以上混ざっていればノイズとみなす。滞在の座標は、50m以内に最も多くの点が集まる点の周囲の中央値とし、少数の飛んだ測位に引っ張られないようにする。間のノイズ点も滞在に含めて移動線から除く。Webでは滞在時間に応じた円、Android/iOSでは軽量な地図マーカーで表示する。滞在表示には開始時刻と終了時刻を使い、元の記録は変更しない。加工済み移動線は滞在内部のサンプルを省略しつつ、滞在の代表点を前後の線で共有して連続させる。現在地は端末・ブラウザの位置レイヤーで表示する。明らかな単発GPSスパイクは前後1点の補間と、移動中に直前の位置へ戻る古い測位（前後の点の間隔が2分以内で、前後を結ぶ線から200m以上かつ前後の距離の2倍・測位精度の4倍以上離れた1〜2点）の補間に加えて、前後2点ずつが100m以内に安定している場合だけ近傍中央値へ表示用座標を補正する。さらに、同じ安定クラスタへ戻る最大2サンプルの短い往復も、各点が35m以上（測位精度がある場合は精度の2倍以上）離れている場合だけ補正し、3サンプル以上続く移動や補正距離35m未満のグレーな点はそのまま残す。元の記録は変更しない。未確定のEXIF写真は、撮影時刻の前後15分以内にある精度100m以下の加工済み位置ログから線形補間または最近傍で求めた表示座標へ自動配置する。手動・推定・削除済み、または元のEXIFへ戻して自動配置を無効化した写真は保存座標を使う。写真は座標を持つ記録だけ地図とTimelineに表示する。加工済み移動線の濃さは現在時刻から古いほど薄くする。地図の表示位置・ズームは初回表示と日付切替時だけ自動調整し、自動記録やバックアップによる記録更新では保持する。

選択日内の滞在区間だけを、代表座標が100m以内なら表示上の同一滞在ポイントへまとめ、訪問回数ごとにセクション化する。Timelineの集約は選択日内で行い、滞在区間・位置ログ自体も統合せず保持する。滞在や「滞在した場所」の行から開く訪問履歴では、全期間の記録から、その場所の1km以内に記録がある日だけを日ごとに滞在判定し、代表座標が100m以内の滞在を新しい順に日付ごとにまとめて表示する（訪問回数・日数・合計時間付き。日付を選ぶとその日のTimelineへ移動）。Android/iOSの滞在ポイント名・住所は端末の逆ジオコーダーから都度取得し、記録や同期データには保存しない。Webは逆ジオコーディングを行わず座標を表示する。

### すべての滞在

地図の「日ごと／すべて」切替で、全期間の滞在を場所ごとにまとめて表示する。滞在は日ごとの滞在判定（Timelineと同じ処理）の結果を使い、全滞在を時刻順に、最も近い場所の100m以内なら同じ場所へまとめる（場所の座標は訪問の中央値）。場所は訪問回数順に並べ、全期間／1年／30日で絞り込める。地図の円は合計滞在時間の対数で大きさを、最終訪問からの経過日数で濃さを決める。場所を選ぶと訪問履歴を表示し、日付を選ぶとその日のTimelineへ移動する。Android/iOSの場所名は、一覧に表示された行だけ端末の逆ジオコーダーから取得する。「すべて」に戻ると、離れる前の地図の表示位置を復元する。

過去日の滞在判定結果は端末内の派生キャッシュにJSON文字列1件として保存する（Webは IndexedDB `remo-stay-index` に端末ストレージIDごと、Androidは `filesDir/stay-index.json` を `AtomicFile` で、iOSは Application Support の `remo-stay-index.json` をアトミック書き込みで保存）。キャッシュは同期・エクスポートせず、いつ破棄しても記録から再計算できる。日ごとに記録の`(id, updatedAt)`から作るフィンガープリントを持ち、一致しない日だけ再計算する（編集・削除・同期・インポートを検知）。アルゴリズムのバージョンまたはタイムゾーンが変わった場合は全体を破棄する。記録中の今日はキャッシュせず常に計算する。再計算は画面の応答性を保つよう、Webは短い単位に分けて、Android/iOSはバックグラウンドで実行し、記録が更新されたら中断して最新の記録でやり直す（完了済みの日は保持する）。滞在の訪問履歴も、キャッシュの準備後はこの滞在一覧から求める。全データ削除時はキャッシュも削除する。

## Privacy

- 位置情報はOS／ブラウザの許可後だけ取得し、アプリ設定から停止できる。
- 元写真・動画本体はAPIへアップロードしない。写真の縮小JPEGだけを認証済みAPI経由でR2へ保存する。
- エクスポートは開始日・終了日を指定し、期間内の位置・写真レコードを時刻・座標・位置精度・種別・枚数付きJSONで行う。写真画像本体は含めず、元の記録をそのまま確認できる。
- ローカル開発用のサンプルデータは `fixtures/timeline/` に置き、本番データや端末の保存先とは分離する。
- 全クエリは認証済みユーザーIDで限定する。
- 端末とクラウドの全記録を削除できる。
- 未ログイン時の削除は端末内だけを対象にし、ログイン時だけクラウド削除を実行する。
- クラウドの記録を削除すると、位置・時刻などの内容はその場で消去し、同期用のIDと更新時刻だけを削除記録（tombstone）として残す。削除記録があるため、他の端末に残っている古いコピーが次の全件同期で再アップロードされることはない。他の端末の記録はその端末を正本として残る。
- 削除記録は90日後に日次のCron Triggerで物理削除する。期限切れのセッションとパスワード再設定用の値も同じジョブで削除する。
- アカウントはパスワードを確認したうえで削除でき、クラウドのバックアップ・セッション・認証情報をすべて削除する。端末内の記録は残す。
- サインイン・新規登録・パスワード再設定・アカウント削除はIPアドレスごとにレート制限する（Workers Rate Limiting、60秒10回）。

写真位置の補正候補は、写真自身を判定材料から除外し、撮影時刻の前後15分以内にある精度100m以下の位置ログをスパイク補正した加工済み座標から線形補間または最近傍で求める。候補はユーザーが適用するまで記録を変更しないが、未確定のEXIF写真の地図・Timeline表示には候補座標を使う。手動指定は地図クリックまたは緯度経度入力で行い、補正済み座標・補正方法・元のEXIF座標を保存する。位置情報を削除した場合も元のEXIF座標は残す。元のEXIFへ戻した場合は自動表示配置を無効化する。

写真ライブラリのインデックスは日付と座標で写真をグループ化しているため、Android/iOSの補正操作は写真グループ単位で適用する。Webの個別インポート写真は1レコード単位で扱う。
