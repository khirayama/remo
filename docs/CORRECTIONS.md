# 補正・統合・場所名

記録（位置サンプル・写真）は変更せず、その上に「補正」と「場所」を重ねて Timeline を直す。3 プラットフォームと API（MCP）が同じ規則で当てはめ、結果は `fixtures/timeline/corrections.cases.json` と `corrections.expected.json` で照合する。

| 困りごと | 操作 | データ |
|---|---|---|
| 大きく飛んだ測位 | 測位の除外 | 補正 `exclude` |
| 続けて滞在していたのに 2 つに分かれる | 滞在をつなげる | 補正 `join_stay` |
| 続けて移動していたのに途中に滞在が入る | 滞在ではない | 補正 `not_stay` |
| 同じ場所の滞在が日によって別の場所になる・座標が少しずれる | 場所に基準点を足す（場所の統合） | 場所の `anchors` |

## 場所（named place）

```ts
type PlaceAnchor = { latitude: number; longitude: number; radiusMeters: number };
type Place = {
  id: string;
  name: string;
  latitude: number;      // 最初の基準点
  longitude: number;
  radiusMeters?: number; // 最初の基準点の半径。省略時 100
  anchors?: PlaceAnchor[]; // 追加の基準点（最大 20）
  mergedInto?: string;   // 統合で消えた場所（deleted）が、統合先の id を指す
  updatedAt: number;     // ミリ秒。新しい方が勝つ
  deleted: boolean;
};
```

- 半径は 25〜500m（範囲外は丸める）。UI の選択肢は 50 / 100 / 200 / 300m。
- **照合（`matchPlace`）**: 削除されていない場所のすべての基準点のうち、点から半径以内にあるものの中で最も近い基準点の場所。どの基準点にも入らなければ名前なし。
- **1 日の Timeline**: 場所に当てはまった滞在は、当てはまった基準点の座標に描き（元の記録は変えない）、`placeId` を持つ。1 日の「滞在した場所」のまとめでは、同じ `placeId` の滞在を 1 か所にまとめる（基準点どうしが 100m より離れていても）。
- **すべての滞在**: 滞在キャッシュは場所と無関係に保存し（場所名を変えてもキャッシュは作り直さない）、表示時に照合する。場所に当てはまった滞在は `named:<placeId>` の 1 か所にまとめ、座標は場所の最初の基準点。残りは従来どおり 100m でまとめる。
- **訪問履歴**: 対象の座標が名前付きの場所に当てはまるなら、その場所に当てはまる滞在。そうでなければ、どの場所にも当てはまらず 100m 以内の滞在（`visitFilter`）。
- **統合**: 場所 A へ「近くの場所」をまとめる。名前のない場所（すべての滞在のまとまり）なら、その座標を半径 100m の基準点として A に足す。名前付きの場所 B なら、B の全基準点を A に足し、B を `deleted: true, mergedInto: A` にする。

## 補正（timeline correction）

```ts
type TimelineCorrection = {
  id: string;            // UUID
  kind: "exclude" | "join_stay" | "not_stay";
  startedAt: number;     // ミリ秒。両端を含む
  endedAt: number;       // startedAt 以上、startedAt + 24 時間以下
  createdAt: number;     // ミリ秒。当てはめる順番
  source: "app" | "mcp"; // mcp は AI ツールが作った補正
  deleted: boolean;      // 作成後に変わるのは deleted（false → true）だけ
};
```

### 当てはめる手順（`analyzeTimeline`）

1. `exclude`: 範囲内の**位置サンプル**を入力から外す（写真は残す）。
2. 従来どおりスパイク補正・滞在判定を行う。
3. `join_stay` と `not_stay` を `createdAt` の古い順（同じなら id の昇順）に当てはめる。新しい補正が後に効くので、重なったら新しい方が勝つ。
   - `not_stay`: 範囲に半分以上入っている滞在を外す（長さ 0 の滞在は開始時刻が範囲内なら外す）。外れた滞在の位置は前後の移動になる。
   - `join_stay`: 範囲と重なる滞在をすべて取り込み、範囲とそれらの滞在の和を 1 つの区間にする。区間内の（補正済みの）位置をすべて 1 つの滞在にし、座標は通常の滞在と同じ規則（50m 以内に最も多く点が集まる点の周囲の中央値）。区間内に位置が 1 つもなければ何もしない。この滞在は `corrected: true`。
   - 当てはめた後は時刻順に並べ、id を `stay:<startedAt>:<順番>` で振り直す。
4. 場所に当てはまった滞在を基準点へ寄せる（1 日の Timeline だけ。滞在キャッシュでは行わない）。
5. 従来どおり徒歩の線を平滑化し、移動・写真の割り当てを作る。

1 日ごとに計算するので、日をまたぐ補正はそれぞれの日の部分にだけ効く。

### 外れ値の候補（`findOutlierCandidates`）

自動補正は 1〜2 点のスパイクしか直さない。補正済みの位置で、前後の点 A・B の間にある 1〜5 点の連続（すべてが滞在の中ならスキップ）について、次をすべて満たす最短の連続を候補にする。

- A→最初の点、最後の点→B の時間がどちらも 0 より大きく 5 分以内
- 連続のすべての点が A・B の近い方から 300m 以上
- A→最初の点、最後の点→B の速さがどちらも 30m/s 以上
- A と B の距離が「連続の点と A・B の近い方との距離の最小値」の半分以下

候補 `{ startedAt, endedAt, eventIds, latitude, longitude, distanceMeters }` は、`exclude [startedAt, endedAt]` で取り除ける。見つけたら連続の次（B）から探し続ける。

## 同期

### 場所（既存の `/api/v1/places` を拡張）

- `GET /api/v1/places` は各場所に `radiusMeters`・`anchors`・`mergedInto` を（値があるときだけ）含める。
- `PUT /api/v1/places` は送らなかった項目をサーバーの値のまま残す（古いアプリが名前を変えても基準点は消えない）。削除すると基準点と半径も消す。
- 端末は送られてきた項目を保存し、編集した場所を送るときは全項目を送る。

### 補正（`/api/v1/corrections`）

- `PUT /api/v1/corrections` `{ "corrections": [TimelineCorrection, ...] }`（1〜200 件）→ `{ "data": { "accepted": n } }`。サーバーは新しい id を追加し、既存の id には `deleted: true` だけを反映する（`source` はサーバーが `app` にする）。削除されていない補正が 10,000 件を超えると `507 storage_limit`。
- `GET /api/v1/corrections?after=<cursor>` → `{ "data": { "corrections": [...], "cursor": <number>, "hasMore": <bool> } }`。`after` 以降に書かれた補正（削除済みを含む）を書いた順に最大 1,000 件返す。`cursor` を次の `after` にし、`hasMore` が false になるまで続ける。最初は `after=0`。
- 端末の手順（場所の同期の直後）: 未送信の補正（作成・削除）を 200 件ずつ送って送信済みにする → カーソル以降を受け取る → 受け取った補正のうち、手元にないものは追加、`deleted` なら手元も削除済みにする。追加・削除のたびに、範囲が掛かる現地の日を「変更された日」にして滞在キャッシュを作り直す。
- カーソルはアカウントごとに持つ。未送信の判定は場所と同じ世代（epoch）方式で、所有アカウントの切り替えで世代が進むと全件を送り直す（サーバーは同じ id を重複して作らない）。
- ログインしていなくても、補正は端末に保存して当てはめる。
- 「すべて削除」は端末の補正も消し、サーバーの補正も物理削除する。アカウント削除でも消える。削除済みの補正は 90 日後にサーバーから消える。

## エクスポート・インポート

JSON（`schemaVersion: 1` のまま）に次を加える。

- `places`: 削除されていないすべての場所
- `corrections`: 範囲内の日に掛かる、削除されていない補正

インポートでは、手元にない id の補正を追加し、場所は新しい方を取り込む。

## アプリの操作

- **滞在**: 「前の滞在とつなげる」（同じ日に前の滞在があるとき。`join_stay [前の滞在の開始, この滞在の終了]`）、「滞在ではない」（`not_stay [開始, 終了]`）。
- **外れ値**: その日に外れ値の候補があれば「飛んだ測位 N か所」を表示し、「除外する」で候補ごとに `exclude` を作る。
- **この日の補正**: その日に掛かる補正を一覧し（種類・時刻・AI が作ったものは「AI」）、1 件ずつ「取り消す」（`deleted: true`）。
- **名前付きの場所**: 半径の選択、基準点の一覧（追加の基準点は外せる）、「近くの場所をまとめる」（1km 以内の、すべての滞在のまとまりと他の名前付きの場所を近い順に表示）。
- **MCP のトークン**: 一覧に、書き込みできるトークン（`scope: "write"`）であることを表示する。書き込みできるトークンの発行は Web だけ。

## MCP

[MCP.md](./MCP.md) を参照。補正と場所の読み書きのツールを持ち、書き込みは `write` のトークンだけが使える。AI が書いた補正は `source: "mcp"` になり、アプリで取り消せる。
